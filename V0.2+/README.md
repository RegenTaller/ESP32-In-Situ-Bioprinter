# Прошивка v0.2: стабилизированная версия

Новая версия прошивки рабочего органа in situ биопринтера для того же контроллера и той же схемы (ESP32 DevKit V1,
2× TMC2130 + NEMA14, 2× ДПТ N20 с энкодерами + TB6612FNG, HC-SR04 — `Scheme.png`). Версия v0.1 в корне репозитория
не изменена.

```
V0.2+/
├── ESP32_InSituBioprinter_V0_2/   скетч Arduino (открывать .ino)
│   ├── ESP32_InSituBioprinter_V0_2.ino   setup / loop
│   ├── Config.h                          пины и константы
│   ├── Settings.h / .cpp                 параметры и позиции в NVS
│   ├── Control.h / .cpp                  задача управления, аварии
│   ├── HeadAxis.h / .cpp                 ось Z: шаги, датчик, слежение
│   ├── Dispenser.h / .cpp                дозатор: энкодеры, ПИД, защита
│   └── Commands.h / .cpp                 команды и телеметрия
├── COMMANDS.md                    список команд
├── README.md                      этот файл
└── sim/                           симуляция логики на ПК
```

## Сборка

- Arduino IDE 2.x или arduino-cli. Плата **ESP32 Dev Module**, разметка по умолчанию.
- Ядро **esp32 by Espressif ≥ 3.0** (проверено на 3.1.1): как и v0.1, используется API таймеров и ledc версии 3.x.
- Библиотека **TMC2130Stepper** (teemuatlut) 2.5.1 — та же, что в v0.1. SimpleKalmanFilter больше не нужна.
- Открыть `ESP32_InSituBioprinter_V0_2/ESP32_InSituBioprinter_V0_2.ino`.

## Изменения в поведении: прочитать до прошивки

- **Слежение включается только командой `track1`.**
- **После первой прошивки ось Z не отхомлена:** нужен `zhome`, `zset<мм>` или `zhomehard`. Позиции из EEPROM v0.1 не читаются.
- **`sp` теперь означает реальную скорость.** В v0.1 головка двигалась вдвое быстрее заданного, поэтому при прежнем значении `sp` она станет вдвое медленнее.
- **Дистанция считается при 343 м/с вместо 335:** показания вырастут на 2,4 %, отступ `sh` может потребовать пересчёта.
- **`kp`, `ki`, `kd` дозатора — в новых единицах, `minDuty` имеет другой смысл.** Старые значения не переносить.
- **У строк телеметрии появилась метка** (`POS,` `VEL,` `HEAD,` `PWM,`). Скрипты обработки нужно поправить.
- **Команды `rk` и `rconst` удалены.**

## Результаты симуляции

`sim/` компилирует файлы прошивки без изменений на ПК; API ESP32 заменён заглушками. Модели:

- шаговый привод по фронтам STEP/DIR;
- HC-SR04 по фронту TRIG;
- два ДПТ с сухим трением на одном толкателе и квадратурные энкодеры.

| Сценарий | Результат |
|---|---|
| Слежение, треугольник 21,5 мм, 4 мм/с, идеальный датчик | ошибка зазора СКО 0,18 мм, макс. 0,48 мм, задержка 40 мс |
| То же с шумом 0,5 мм, 5 % перескоков на период и 1 % пропусков эха | СКО 0,36 мм, макс. 1,37 мм, задержка 40 мс, ложных аварий нет |
| То же при 2 мм/с (идеальный / с артефактами) | СКО 0,08 / 0,32 мм, задержка 35 / 50 мс |
| Обрыв датчика при слежении | авария через 100 мс, головка отведена в 0 мм |
| Подача на скорости печати 262 тик/с, 10 с | 2621 тик из 2621; окон с остановкой и обратным ходом 0 % |
| Заклинивание 0,5 с при 2000 тик/с, выброс после освобождения | 110 тик ≈ 2,3 мкл (с `emax`) против 896 тик ≈ 18,6 мкл (без ограничителя) |
| Заклинивание дольше `jamt` | авария через 1,07 с, отвод на 140 тик |
| Зависание контура управления | шаги остановлены через ~50 мс, ДПТ на тормозе |

**Насколько корректно сравнение.** Цифры симуляции нельзя прямо сравнивать с экспериментом ВКР (рис. 16–17: задержка 400 мс, ошибка в несколько мм):

- В симуляции поверхность плоская.
- Смещение датчика от сопла не моделируется.
- Артефакты HC-SR04 заданы предположительно.
- Параметры моторов подобраны по порядку величины.

Симуляция проверяет логику прошивки и сравнивает варианты между собой. Реальную точность на стенде она не предсказывает.

## Первый запуск на стенде

1. Без пациента и без биочернил; для дозатора — вода или пустой шприц.
2. Прошить, открыть монитор порта 115200, `status`.
3. **Направление Z:** `zjog2` — головка должна пойти вниз. Если пошла вверх, `zdir1`.
4. **Хоминг и ход:** поднять головку до упора командами `zjog-…`, затем `zhome`. Проверить ход небольшими `zgo`, задать `zmax` по механике.
5. **Датчик:** `Head1`, поднести пластину и сверить с линейкой; при необходимости `uscal`/`usoff`.
6. **Отступ:** поставить сопло на нужный зазор, взять из `status` текущие `est` (дистанция) и `pos`; `sh` = est − pos.
7. **Слежение:** `track1`, двигать пластину рукой. Проверить `track0`, `stop` и отсоединение провода ECHO: должны быть `FAULT SENSOR` и отвод головки.
8. **Направление дозатора:** `vel1000; Z0.2` — толкатель должен идти к поршню, и позиция в `status` должна расти. Если моторы крутятся, а энкодеры считают в обратную сторону, остановить (`stop`) и поменять `ENC1_SIGN`/`ENC2_SIGN` в `Config.h`.
9. **Настройка ПИД дозатора** на скорости печати, лог `POS1; VELS1; PWM1; millis1`:
   - `minDuty` — чуть ниже порога страгивания;
   - `kv` — чтобы `PWM` почти не зависел от `kp`;
   - затем `kp` и `ki`. Цель — нет окон с нулевой и отрицательной скоростью.
10. **Заклинивание:** на воде пережать сопло — должна появиться `FAULT JAM` и отвод. Подобрать `emax`/`jamt`, чтобы не было ложных срабатываний.
11. `save`.

## Чего прошивка не исправляет: ограничения железа

- **Датчик смещён от сопла** (по рендеру — на 5–7 см). На наклонной или выпуклой поверхности зазор под соплом отличается от измеренного на миллиметры, а это больше слоя 0,34 мм.
- **HC-SR04:** паспортная точность ~3 мм (на плоской жёсткой мишени), перескоки на период несущей (~4,3 мм), конус ~15°. Нужен другой принцип измерения, например лазерная триангуляция.
- **Оба TMC2130 на одном CS и одной линии MISO:** чтение регистров (диагностика, StallGuard, перегрев) ненадёжно, поэтому хоминг без концевика сделан об упор. Нужны раздельные CS или daisy-chain.
- **Уровни 5 В:** ECHO у HC-SR04 с питанием 5 В даёт 5 В на GPIO4 (ESP32 — 3,3 В). Нужен делитель или HC-SR04P. То же касается энкодеров с подтяжкой к 5 В на GPIO32–35.
- **GPIO34/35** не имеют внутренних подтяжек: при выходах энкодера типа «открытый коллектор» нужны внешние резисторы.
- **STBY у TB6612** на схеме не разведён: он должен быть подтянут к VCC.
- **Провода Dupont на подвижном роботе** — источник обрывов. Нужны разъёмы с фиксацией. Обрыв ECHO/TRIG v0.2 обнаруживает, обрыв энкодера — частично (через `SKEW`/`JAM`).
- **Два ДПТ на одном толкателе.** На 0,03 мм/с ДПТ работает в зоне сухого трения; шаговый привод дозатора был бы проще и точнее.
- **Bluetooth без аутентификации:** любой в радиусе действия может отправить команду. Если Bluetooth не нужен, `#define BT_ENABLED 0` в `Config.h`.

## Архитектура

- **Прерывание таймера 50 кГц:** генерация шагов, импульс TRIG датчика, сторожевой таймер. Только целочисленная арифметика.
- **Прерывание ECHO:** длительность эха по `esp_timer` (1 мкс ≈ 0,17 мм).
- **Прерывания энкодеров:** декодирование ×4, метка времени фронта.
- **Задача управления** (FreeRTOS, ядро 1, приоритет 5, 1 кГц):
  - датчик и α-β фильтр;
  - ось Z — каждую 1 мс;
  - дозатор — каждые 10 мс;
  - аварии.
- **`loop()`:** приём команд, события, телеметрия, сохранение позиций.
- Общее состояние защищено мьютексом. В `loop()` под мьютексом выполняются только присваивания, без вывода в порт.

```
cd V0.2+/sim

```
